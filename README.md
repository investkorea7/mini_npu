# Mini NPU Simulator 리포트

## 1. 실행 방법
본 프로그램은 파이썬 표준 라이브러리만을 활용하여 작성되었으며, 터미널에서 다음 명령어로 실행합니다.

python3 main.py

* **모드 1 선택 (1 입력)**: 3x3 필터 A, B 및 패턴 데이터를 직접 콘솔로 입력받아 연산 점수, 시간(ms), 판정 결과를 출력합니다.
* **모드 2 선택 (2 입력)**: 동일 디렉토리의 data.json 파일을 읽어와 크기별(5x5, 13x13, 25x25) 패턴을 일괄 분석하고 성능 표 및 결과 요약을 출력합니다.

## 2. 구현 요약

* **라벨 정규화 (Standardization)**: 입력 데이터나 Expected 값으로 전달되는 '+', 'cross', 'x' 등의 다양한 표현을 내부 표준 라벨인 Cross와 X로 통일하여 판정 로직의 일관성을 확보했습니다.
* **새 라벨 확장 절차**: 향후 새로운 패턴 라벨을 추가할 경우 다음 4단계를 권장합니다. (1) 정규화 함수(normalize_label) 규칙 추가 -> (2) 판정 로직 반영 -> (3) 출력 포맷 수정 -> (4) 테스트 셋 추가 및 검증.
* **MAC (Multiply-Accumulate) 연산**: 외부 라이브러리(NumPy 등) 없이 순수 Python 이중 반복문(for)을 통해 패턴과 필터 간 위치별 곱셈 및 누적합을 구현했습니다. 논리적으로 MAC 연산 점수가 증가할수록 필터와 패턴 간의 겹치는 특징이 많아져 기하학적 유사도 역시 증가함을 의미합니다.
* **동점 및 오차 처리 정책 (Epsilon)**: 부동소수점 오차를 고려하여 두 점수 차이가 1e-9 미만일 경우 UNDECIDED(판정 불가)로 분류했습니다. 모드별 정책 차이로, 대화형(모드 1)은 사용자에게 즉각 안내하여 유연성을 주지만, 자동화된 배치 처리(모드 2)에서는 엄격한 신뢰성을 위해 동점을 즉각 FAIL로 처리합니다.
* **예외 처리 및 안정성**: 모드 1의 경우 사용자 잘못 입력 시 안내 문구 출력 후 재입력을 유도하며, 모드 2의 경우 스키마/크기 불일치가 발생해도 프로그램 중단 없이 해당 케이스만 FAIL 처리하도록 구성했습니다.

## 3. 결과 리포트

### (1) 실패 원인 분석 (FAIL 케이스 검증)
현재 검증용 데이터셋(data.json) 실행 결과 총 4개 테스트 중 4개 통과(FAIL 0개)를 기록했습니다. 
이번 테스트에서 실패 케이스가 발생하지 않은 원인은 다음과 같습니다. 첫째, 라벨 정규화 함수(normalize_label)를 통해 'x'와 '+' 같은 다양하게 표기된 입력값을 내부 표준 규격인 'X'와 'Cross'로 사전 처리했기 때문입니다. 둘째, 부동소수점 오차 완화를 위한 Epsilon 기반 비교 정책(1e-9)을 도입하여 수치 비교 시 발생할 수 있는 오판정 가능성을 사전에 차단했기 때문입니다. 

또한 JSON 문법 오류, filters/patterns 스키마 오류, 필터 및 패턴 키 형식 오류, 배열 크기 불일치, Cross/X 필터 누락, expected 라벨 오류가 발생하더라도 가능한 경우 프로그램 전체가 중단되지 않도록 처리하고, 패턴 단위 오류는 해당 케이스만 FAIL로 기록하도록 구성했습니다.

### (2) 시간 복잡도 분석 ($O(N^2)$)
성능 분석 결과, 패턴 및 필터의 가로/세로 크기 N이 커짐에 따라 MAC 연산 횟수가 $N^2$에 비례하여 증가하고, 측정 시간도 전반적으로 증가하는 경향을 확인할 수 있습니다.
* 3x3 입력 (연산 횟수: 9회) -> 평균 연산 시간: 약 0.002 ms
* 5x5 입력 (연산 횟수: 25회) -> 평균 연산 시간: 약 0.007 ms
* 13x13 입력 (연산 횟수: 169회) -> 평균 연산 시간: 약 0.035 ms
* 25x25 입력 (연산 횟수: 625회) -> 평균 연산 시간: 약 0.094 ms

이러한 수치적 증가는 MAC 연산의 구조적 특징에 기인합니다. 2차원 $N \times N$ 데이터 구조에서 모든 위치의 값을 포개어 곱하고 더하기 위해 이중 반복문을 수행하므로, 전체 연산 횟수는 정확히 $N \times N = N^2$번이 됩니다. 따라서 본 시뮬레이터의 시간 복잡도는 $O(N^2)$입니다. 
만약 1000x1000과 같은 대형 시나리오로 확장할 경우, CPU 기반의 직렬 연산은 기하급수적인 시간 지연뿐만 아니라 막대한 메모리 요구량(캐시 미스 등)으로 인한 심각한 병목 현상에 직면하게 됩니다. 따라서 대형 데이터 처리 시에는 메모리 대역폭 한계 극복과 우선적인 최적화 항목으로 수천 개의 MAC 연산을 동시에 병렬로 처리하는 NPU 하드웨어 도입이 필수적입니다.
